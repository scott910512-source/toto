Problem

무엇이 막혔나

Part 1에서 만든 데이터 수집(EHR API 직접 호출)이 인증 때문에 지속 실패했다.

서버 응답은 계속 SESSION_LOG_OUT — "세션이 종료되었습니다". 원인은 회사가 SSO(통합 로그인) 방식이라는 점이었다.

  • 한계
    브라우저에서 복사한 sessionId·쿠키는 시간이 지나면 만료 → 매번 수동 갱신 불가
  • 한계
    SSO라 아이디/비번 로그인 요청 자체가 없어 자동 로그인 재현 불가
  • 한계
    sessionId는 JS 클로저에 숨고, 데이터는 위젯(iframe) XHR로 로드 → 추적 까다로움
  • 한계
    내부망(폐쇄망)이라 pip 설치 불가, 화면 잠금 시 pyautogui 불가
Attempts

시도와 그 한계

정공법부터 우회까지 차례로 시도했고, 각각 벽에 부딪혔다.

시도방식결과
① 키 복사브라우저 sessionId·쿠키를 코드에 입력만료로 매번 실패
② 자동 로그인requests로 로그인 재현SSO라 불가
③ 북마클릿로그인된 브라우저에서 데이터를 JSON으로 저장 → 파이썬이 읽기동작하나 수동·누더기
④ Playwright로그인된 브라우저를 코드로 직접 제어채택 ✅

핵심 통찰

“인증을 흉내내려 하지 말고, 이미 인증된 브라우저를 그대로 운전하자.” — 이 전환이 모든 문제를 한 번에 풀었다.

Pivot

왜 Playwright인가

브라우저 자동화 라이브러리. 화면 좌표가 아닌 브라우저 프로토콜로 제어한다.

Architecture

확정된 최종 구조

2단계 접속으로 세션을 잇고, 화면 데이터를 직접 읽어 기존 가공 파이프라인에 연결.

중간 서버→ 최종 EHR 페이지→ DOM 표 추출→ 가공·정렬→ 이미지→ 바탕화면 / 근무표2
1

2-hop 접속 (중간 서버 → 최종 사이트)

같은 브라우저 컨텍스트로 중간 서버를 먼저 거쳐 세션을 수립한 뒤, 최종 EHR 페이지로 이동. 쿠키·세션이 그대로 따라가 인증이 유지된다.

2

화면(모든 프레임) 데이터 추출

메인 + iframe을 순회하며 근무 키워드가 든 <table>을 읽어 [이름·직책·형태·장소] 구조로 수집.

3

기존 파이프라인 재사용

직책 기준 파싱 → 그룹 매핑 → 우선순위 정렬 → 색상 표 이미지 → 바탕화면 지정 → 1·2근 필터(근무표2)까지 Part 1 코드를 그대로 연결.

4

백그라운드 & 갱신 시간 표시

headless=True로 창 없이 조용히 실행. 표 상단에 갱신 날짜·시간을 얹어(이미지 위 PIL 오버레이) 최신화 여부를 한눈에 확인.

Notes

유의 사항

· 사내 EHR 데이터·브라우저 자동화는 회사 보안정책 준수 범위 내에서 운영한다.
