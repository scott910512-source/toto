Overview

한눈에 보기

수작업으로 확인하던 근무 현황을, 데이터를 직접 받아 표 이미지로 만들고 바탕화면에 자동 반영하는 흐름까지 완성했습니다.

🔌

데이터 직접 수집

화면 자동화(pyautogui) 방식에서 → EHR API를 직접 호출하는 방식으로 전환하여 즉시 데이터 확보.

🧮

자동 분류·정렬

그룹 매핑과 우선순위 규칙으로 전체 인원을 자동 구분·정렬.

🖼️

이미지 리포트

색상 구분·글자 자동 축소가 적용된 표 이미지를 생성하여 바탕화면에 자동 지정.

⏱️

무인 스케줄링

작업 스케줄러로 주기 실행. 화면 잠금 상태에서도 바탕화면 갱신.

Objective

목표

“VDI 안의 근무 데이터에 접속해, 근무표를 표 형태로 받아 바탕화면으로 저장한다.”

여기서 출발해, 단순 저장을 넘어 분류·시각화·자동 갱신·사내 공유까지 확장하는 것을 목표로 작업을 진행했습니다.

What We Did

진행 내용

데이터 접근 분석부터 자동화 배포까지의 단계별 작업입니다.

1

데이터 접근 경로 분석

브라우저 개발자도구(F12) Network 탭에서 근무 데이터를 내려주는 엔드포인트 serviceBroker.h5 확인. 요청(POST·JSON)과 응답 구조를 분석했습니다.

2

요청·응답 구조 해석

입력셋(_01)과 출력셋(_02) 패턴을 파악. 응답의 근무 현황 배열에서 구성원·직책·형태·장소 컬럼을 식별했습니다.

3

인증 구조 확인

세션 기반 인증(세션 식별자 + 쿠키)임을 확인. 로그인된 세션 값을 재사용하는 방식으로 데이터 호출을 재현했습니다.

4

수집 방식 전환 (pyautogui → API 직접 호출)

기존 화면 자동화 기반 수집을, requests로 API를 직접 호출하는 방식으로 개선하여 더 빠르고 안정적으로 데이터를 받도록 했습니다.

5

데이터 가공 · 분류

그룹 매핑(이름 → 소속그룹)과 우선순위 규칙(팀장·Office·1근/2근·공장별)으로 전체 인원을 자동 분류하고 순번으로 정렬했습니다.

6

표 이미지 생성

우선순위별 색상 구분(공장별 농도 차등), 칸을 넘치는 글자의 자동 축소를 적용해 가독성 높은 표 이미지를 생성했습니다.

7

바탕화면 자동 지정

고정 파일명으로 덮어쓰기 저장 후, 검정 배경 캔버스에 배치하여 바탕화면으로 자동 설정.

8

전송용 근무표2 + 신선도 검증

1근·2근 인원만 추린 별도 이미지를 생성하고, 파일 수정 시각이 8시간 이내인지 확인 후 전송하도록 하여 오래된 데이터 오발송을 방지했습니다.

9

스케줄러 자동화

Windows 작업 스케줄러에 등록(로그온 세션 실행)하여 주기적으로 자동 실행. 화면 잠금 상태에서도 바탕화면 갱신이 가능하도록 구성했습니다.

다음 단계 핵심

사내 메신저 CUBE로의 전송을 안정화하려면, 화면 자동화 대신 공식 API 또는 DB 접근 경로가 제공되는지 확인하는 것이 우선입니다. 접근 수단이 확보되면 잠금 상태·해상도 변화와 무관하게 신뢰성 있는 자동 전송이 가능해집니다.

Notes

유의 사항

· 사내 인사(EHR) 데이터 및 메신저 자동화는 회사 보안정책 준수 범위 내에서 운영합니다.
· 인증 정보(세션·쿠키)와 개인정보는 외부 공유·저장하지 않습니다.
· 화면 자동화(붙여넣기·전송)는 화면 잠금 상태에서는 동작하지 않습니다.
