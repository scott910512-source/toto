# 또또 자료 백업

Supabase 무료 플랜은 자동 백업이 없습니다. 2026-10-12 에 프로젝트가 멈췄을 때
"자료가 안전한가" 의 답이 '앱에서 손으로 내보낸 파일' 뿐이었습니다. 그래서
GitHub Actions 가 **매일 기록을, 일요일에는 사진까지** 꺼내 잠가서 90일 보관합니다.

## 한 번만 하면 되는 설정 (3개 비밀)

GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `TOTO_BACKUP_EMAIL` | 승인된 가족 계정 이메일 (관리자 계정 권장 — 나만보기 사진까지 담깁니다) |
| `TOTO_BACKUP_PASSWORD` | 그 계정 비밀번호 |
| `TOTO_BACKUP_PASSPHRASE` | 백업 파일을 잠그는 암호. **아무 데나 적어두세요 — 잃어버리면 백업을 못 엽니다** |

`service_role` 키는 쓰지 않습니다. 가족 계정으로 로그인해 RLS 가 허락하는 만큼만
읽습니다 — 그게 가족이 앱에서 보는 전부입니다.

비밀이 없으면 작업이 "비밀이 없습니다: …" 로 실패하고, 실패하면 GitHub 이
저장소 주인에게 메일을 보냅니다. 그게 알림입니다.

## 어디에 쌓이나

GitHub → **Actions → 또또 백업 → 실행 하나 → Artifacts**.
`또또백업-YYYY-MM-DD-기록만.tar.gz.enc` (매일) · `…-사진포함.tar.gz.enc` (일요일).
90일 지나면 GitHub 이 지웁니다. 공개 저장소라 누구나 내려받을 수 있으므로
**반드시 암호화**돼 있습니다.

## 푸는 법 (맥·리눅스 터미널)

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 \
  -in 또또백업-2026-10-19-사진포함.tar.gz.enc -pass pass:'비밀암호' | tar -xz
```

`또또백업_2026-10-19.json` 이 나옵니다.

## 복원

앱 → **더보기 → 백업 가져오기** 에 그 JSON 을 넣습니다. 앱이 손으로 내보낸
백업과 **같은 형식(v3)** 이라 그대로 들어갑니다. 가져오기는 먼저 무엇이 들어
있는지(기록·사진 수) 보여주고, 사진이 없는 '기록만' 파일이면 사진은 건너뜁니다.

## 손으로 돌리기

```bash
TOTO_BACKUP_EMAIL=... TOTO_BACKUP_PASSWORD=... npx vite-node tools/backup.ts --photos --out ./backup-out
```

## 왜 이렇게 만들었나

- 담긴 수가 DB 수와 다르면 **실패로 끝냅니다**. 조용히 반쪽 백업을 남기지 않습니다.
- 잠근 파일을 **그 자리에서 다시 풀어** 정말 열리는지 확인한 뒤에 보관합니다.
- 로직은 `src/lib/backupRemote.ts` 에 있고 가짜 서버로 테스트합니다
  (`backupRemote.test.ts`). 1000행 상한 페이지 나누기, 로그인 실패 문구,
  사진 한 장 실패, 설정 파일 읽기까지.
- GitHub 스케줄은 기본 브랜치의 워크플로만 돌리므로, 기본 브랜치의
  "Supabase 깨우기" 작업이 매일 또또 브랜치를 받아 이 백업을 함께 돌립니다.
