# Supabase SQL — 무엇을 어떤 순서로 실행하나

Supabase 대시보드 → **SQL Editor** → 새 쿼리 → 파일 내용 전체 붙여넣기 → **RUN**.

모두 **여러 번 실행해도 안전**하게 써 두었습니다. 실수로 두 번 돌려도 데이터가
지워지지 않습니다.

## 순서

| 순서 | 파일 | 무엇을 하나 | 이미 했나 |
|---|---|---|---|
| 1 | `schema.sql` | 프로필 · 앨범 · 사진 · 비공개 버킷 · 기본 권한 | ✅ |
| 2 | `schema-v2.sql` | 육아기록 · 아기정보 · 저장한 사진 · 좋아요 | ✅ |
| 3 | `schema-v3.sql` | **가족 분리** — 집마다 따로 보이게 | ✅ |
| 4 | `migrations/004_security_fix.sql` | 가입 보안 구멍 세 개 막기 | ⬜ **해야 함** |
| 5 | `migrations/005_storage_scope.sql` | 사진 파일 권한을 가족별로 좁히기 | ⬜ **해야 함** |

## 4번 — `004_security_fix.sql`

없으면 이런 일이 생깁니다.

- 초대코드를 **틀리게** 적고 가입하면, 조용히 **새 가족**이 만들어져 혼자
  텅 빈 집에 들어갑니다. (앱이 가입 전에 코드를 확인하도록 고쳤지만,
  DB 쪽도 막아야 확실합니다)
- 마지막 관리자가 자기 권한을 낮추면 **아무도 승인해 줄 수 없는 집**이 됩니다.

## 5번 — `005_storage_scope.sql`

`schema-v3.sql` 에서 사진 경로를 `<가족ID>/연/월/...` 로 바꿨지만, 그 전에
올라간 옛 경로(`연/월/...`)를 계속 읽게 하려고 예외를 뒀습니다. 그 예외가
**"네 자리 숫자로 시작하는 모든 파일"** 을 모든 가족에게 열어 둡니다.

파일을 옮기지 않고, "그 파일을 가리키는 사진 기록이 우리 가족 것일 때만"
열어주는 방식으로 바꿉니다. 덤으로 나만보기도 DB 권한으로 한 번 더 막고,
다른 집 관리자가 우리 파일을 덮어쓰거나 지우지 못하게 합니다.

이 파일이 정말 구멍을 막는지는 사람 눈이 아니라 DB 에게 물어 확인합니다.

```bash
npm run test:sql
```

임시 DB 를 새로 만들어 1~5번을 순서대로 올린 뒤, 두 가족·네 사람·사진
네 장으로 22가지를 확인합니다. **운영 DB 는 건드리지 않습니다.**
CI 에서도 매번 돌아갑니다.

## 그 밖에

- `fix-split-user.sql` — 다른 집 엄마가 v3 이전에 가입해 또또네로 묶여 버린
  경우, 그 사람만 자기 가족으로 떼어냅니다. 파일 안에 이메일을 적는 곳이
  있습니다.

## 하지 않는 것

- 테이블을 지우거나(`drop`) 초기화하지 않습니다.
- 사진 파일을 지우거나 옮기지 않습니다.
- 기존 사용자 ID 를 바꾸지 않습니다.
- 비밀 키(`service_role`, `sb_secret_...`)는 어떤 파일에도 넣지 않습니다.
  프론트에 들어가는 건 공개용 `anon` / `sb_publishable_...` 키뿐입니다.
